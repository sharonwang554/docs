Custom pages allow you to quickly create standalone web pages (like `/p/food-bank` or `/p/youth-ministry`) without writing new Svelte components. You define the content directly within your church's site configuration file using the built-in helper functions, and the site automatically renders the page and adds it to the navigation menu.

<Aside type="tip">
  Use custom pages for content that fits standard layouts (text, features, galleries). If your page requires complex interactive functionality (like a custom form or calculator), create a dedicated Svelte route in `src/routes/` instead.
</Aside>

## Define a custom page

Use the `defineCustomPage()` helper function in your site configuration profile (`sites/<your-church>.config.ts`).

<Steps>

1. Import the helper functions from the configuration utility:

   ```ts
   import { defineCustomPage, defineSection } from "../src/lib/config/site";
   ```

2. Locate the `customPages` array in your `SiteTemplateConfig` object. If it doesn't exist, add it:

   ```ts
   export const yourChurchConfig: SiteTemplateConfig = {
     // ... other config ...
     customPages: [
       // Add pages here
     ],
   };
   ```

3. Call `defineCustomPage()` to create your page, configuring the bilingual titles, navigation placement, and content sections:

   ```ts
   customPages: [
     defineCustomPage({
       slug: "food-bank",
       titleZh: "愛心食物銀行",
       titleEn: "Food Bank Ministry",
       subtitleZh: "傳遞溫暖、分享物資",
       subtitleEn: "Sharing food and God's love",
       showInNav: true,
       navGroup: "churchLife", // Options: "aboutUs", "resources", "churchLife", "topLevel"
       navOrder: 2,
       sections: [
         // Add sections here
       ]
     })
   ]
   ```

</Steps>

### Navigation settings

Setting `showInNav: true` automatically adds your custom page to the site's desktop and mobile navigation menus.

- `navGroup`: Determines which dropdown menu the page appears under.
- `navOrder`: Determines the position within that dropdown (lower numbers appear first).

## Add content sections

The `sections` array inside `defineCustomPage` accepts a list of section blocks. Use the `defineSection()` helper to construct these blocks easily.

Each section requires an `id` and a `type`. Available section types include:
- `text`: Standard bilingual text block
- `features`: A grid of items with titles and descriptions
- `cta`: Call-to-action banner
- `hero`: Page header (often used automatically, but can be manually placed)
- `gallery`: Image grid
- `faq`: Collapsible questions and answers
- `richText` / `html`: Advanced formatting

### Example section: Text block

```ts
defineSection({
  id: "intro",
  type: "text",
  titleZh: "社區物資關懷計畫",
  titleEn: "Community Food Assistance",
  contentZh: "食物銀行每月針對有需求的社區住戶與急難家庭提供協助...",
  contentEn: "Our Food Bank distributes essential supplies every month...",
})
```

### Example section: Features list

For section types like `features`, use the `items` array to define the individual grid elements:

```ts
defineSection({
  id: "services",
  type: "features",
  titleZh: "服務項目與領取方式",
  titleEn: "How We Help & Distribution",
  items: [
    {
      titleZh: "每月物資包發放",
      titleEn: "Monthly Care Packages",
      descZh: "於每月第二與第四個週六上午 10:00 發放。",
      descEn: "Distributed on the 2nd and 4th Saturday of each month.",
    },
    {
      titleZh: "急難家庭到府關懷",
      titleEn: "Emergency Home Visits",
      descZh: "針對突發遭遇困難的家庭，提供即時物資支持。",
      descEn: "Immediate essential food items for families facing urgent crises.",
    }
  ]
})
```

## How rendering works

When a user visits `/p/food-bank`, SvelteKit's dynamic routing catches the URL using `src/routes/[[lang]]/p/[slug]/+page.server.ts`. 

The server fetches the active site configuration, finds the matching page in the `customPages` array by its slug, and passes the data to `src/routes/[[lang]]/p/[slug]/+page.svelte`.

The Svelte page component then iterates through the `sections` array and renders each one using `<CustomSectionRenderer {section} {lang} />`, automatically handling bilingual toggle states and SEO metadata.
