The Raised Church website utilizes a continuous deployment pipeline managed by **Vercel**. Any changes pushed to the `main` branch on GitHub, or any content published in Contentful, will automatically trigger a rebuild and deployment of the site.

## Hosting Platform: Vercel

We chose Vercel for hosting due to its first-class support for SvelteKit and zero-configuration Edge Network. 

### SvelteKit Vercel Adapter

The project uses `@sveltejs/adapter-vercel` to build the application. This adapter automatically optimizes SvelteKit routes:
- Server-side rendered pages (`+page.server.ts`) are compiled into Vercel Serverless Functions.
- Static assets (images, CSS) are distributed across Vercel's Global Edge Network.

To verify the adapter configuration, check `svelte.config.js`:
```javascript
import adapter from '@sveltejs/adapter-vercel';
import { vitePreprocess } from '@sveltejs/vite-plugin-svelte';

/** @type {import('@sveltejs/kit').Config} */
const config = {
	preprocess: vitePreprocess(),
	kit: {
		adapter: adapter({
            // Default options usually suffice, but we can specify runtime (e.g., node18) here if needed
        })
	}
};

export default config;
```

## Environment Variables

For the build to succeed on Vercel, the following environment variables must be configured in the Vercel Project Settings:

- `CONTENTFUL_SPACE_ID`: The ID of the Contentful space.
- `CONTENTFUL_ENVIRONMENT`: Usually `master`.
- `CONTENTFUL_ACCESS_TOKEN`: The Delivery API token for retrieving published content.

<Aside type="danger">
Never expose `CONTENTFUL_ACCESS_TOKEN` to the client. Always keep it in server-side files (`.server.ts`) and access it via `$env/dynamic/private` or `$env/static/private`.
</Aside>

## Contentful Webhooks (Auto-Rebuild)

Because SvelteKit caches server responses and builds static assets, the site needs to be rebuilt whenever church staff update content in Contentful (e.g., publishing a new sermon).

We achieve this using Contentful Webhooks and Vercel Deploy Hooks.

<Steps>
1. **Create Vercel Deploy Hook**:
   - In Vercel, go to Settings -> Git -> Deploy Hooks.
   - Create a new hook named "Contentful Update".
   - Vercel provides a unique URL (e.g., `https://api.vercel.com/v1/integrations/deploy/prj_xyz/xyz`).
2. **Configure Contentful Webhook**:
   - In Contentful, go to Settings -> Webhooks.
   - Create a new Webhook pointing to the Vercel Deploy Hook URL.
   - Set the triggers to fire on **Publish** and **Unpublish** events for all Entry types.
</Steps>

Now, when a staff member hits "Publish" in Contentful, Vercel starts a new build. The process takes approximately 90 seconds.

## Preview Deployments

Vercel automatically creates preview environments for:
- Every Pull Request submitted to the GitHub repository.
- Every branch pushed to GitHub (other than `main`).

These preview URLs (e.g., `https://raised-church-website-git-feature-calendar.vercel.app`) are excellent for sharing progress with church stakeholders before merging to production. 

We currently do *not* use Contentful Preview API for CMS drafts to keep the setup simple for the church staff, but this can be integrated in the future if a staging Contentful environment is required.

## Rollback Procedure

If a bad deployment breaks the live site (e.g., a buggy code push or a critical CMS schema change), Vercel allows instant rollbacks:

1. Log into the Vercel Dashboard.
2. Go to the "Deployments" tab for the Raised Church project.
3. Find the last known working deployment (marked with a green dot).
4. Click the three dots (options) next to the deployment and select **Assign Custom Domains** or **Promote to Production**.
5. The rollback is instant, as the previous build artifacts are already cached on Vercel's edge nodes.
