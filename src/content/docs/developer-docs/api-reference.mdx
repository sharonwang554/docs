This specification provides exhaustive technical reference documentation for the core HTTP endpoints powering our production web applications, headless content delivery systems, and external educational platform integrations across [sharonwang.me](https://sharonwang.me) and [raisedchurch.com](https://raisedchurch.com).

All endpoints accept and return UTF-8 encoded `application/json` payloads unless specified otherwise. Requests must include appropriate authentication credentials and adhere to strict JSON Schema contracts to prevent immediate client-side rejection by our API gateway security layers.

## 1. Raised Church Contentful Webhook Pipeline

Our headless CMS architecture utilizes Contentful webhooks to trigger event-driven **On-Demand Incremental Static Regeneration (ISR)** in Next.js. Whenever pastoral staff or content editors publish, update, or unpublish sermons, ministry events, or community announcements, Contentful dispatches a signed webhook payload to our serverless revalidation controller.

### Endpoint Details

* **URL:** `POST https://raisedchurch.com/api/webhooks/contentful`
* **Authentication:** HMAC-SHA256 Cryptographic Signature Verification via `X-Raised-Signature` header.
* **Rate Limit:** 60 requests / minute per originating IP subnet.

### Request Headers

| Header Name | Required | Description & Expected Value |
| :--- | :--- | :--- |
| `Content-Type` | Yes | Must be `application/vnd.contentful.management.v1+json` or `application/json`. |
| `X-Contentful-Topic` | Yes | Specifies the lifecycle event triggered (e.g., `ContentManagement.Entry.publish`). |
| `X-Contentful-Webhook-Name` | Yes | The registered name of the webhook configuration (`RaisedChurch-Prod-ISR-Sync`). |
| `X-Raised-Signature` | Yes | The hexadecimal `HMAC-SHA256` digest computed using the raw request body and our shared webhook secret. |

<Aside type="caution" title="HMAC Signature Verification Requirement">
  To prevent unauthorized actors from triggering arbitrary cache purges or server-side revalidations, our endpoint computes an HMAC-SHA256 hash using the raw request body bytes and `CONTENTFUL_WEBHOOK_SECRET`. If `crypto.timingSafeEqual()` reveals a mismatch against `X-Raised-Signature`, the request is rejected immediately with `401 Unauthorized`.
</Aside>

    ```javascript
    const webhookUrl = 'https://raisedchurch.com/api/webhooks/contentful';

    const payload = {
      sys: {

    };

    const bodyString = JSON.stringify(payload);
    const signature = crypto.createHmac('sha256', secret)

      .digest('hex');

        'X-Contentful-Topic': 'ContentManagement.Entry.publish',
        'X-Contentful-Webhook-Name': 'RaisedChurch-Prod-ISR-Sync',
        'X-Raised-Signature': signature
      },
      body: bodyString
    });

    const data = await response.json();
    console.log(`Revalidation status [${response.status}]:`, data);
    ```

## 2. 3D Space Portfolio State & i18n Sync

Sharon Wang's interactive 3D portfolio at [sharonwang.me](https://sharonwang.me) maintains localized string preferences (`i18n`) and Three.js / WebGL rendering telemetry across browser sessions. This endpoint persists client state to a high-speed Redis session store and dynamically adapts 3D shader complexity and post-processing quality based on client device capabilities.

### Endpoint Details

* **URL:** `PUT https://sharonwang.me/api/v1/locale`
* **Authentication:** Session cookie or `X-Session-ID` header.
* **Rate Limit:** 120 requests / minute per user session.

### JSON Request Payload Schema

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "LocaleAndWebGLStateUpdateRequest",
  "type": "object",
  "properties": {
    "locale": {
      "type": "string",
      "enum": ["en", "zh-TW", "ja"],
      "description": "User interface localization preference."
    },
    "quality": {
      "type": "string",
      "enum": ["ultra", "balanced", "performance"],
      "description": "WebGL rendering tier governing shadow map resolution, bloom passes, and anti-aliasing."
    },
    "gpuTelemetry": {
      "type": "object",
      "properties": {
        "fpsAverage": { "type": "number", "minimum": 1, "maximum": 240, "example": 59.8 },
        "renderer": { "type": "string", "example": "ANGLE (Apple, Apple M3 Max, OpenGL Engine)" },
        "devicePixelRatio": { "type": "number", "example": 2.0 }
      },
      "required": ["fpsAverage", "renderer"]
    }
  },
  "required": ["locale", "quality"]
}
```

### JSON Response Schema (`200 OK`)

## 3. Canvas LMS REST Grade Passback Integration

When evaluating student assignments or running automated grading pipelines in AWS Lambda, our system syncs computed scores and structured instructor feedback directly to the institutional **Canvas LMS** gradebook via REST endpoints.

### Endpoint Details

* **URL:** `POST /api/v1/courses/:course_id/assignments/:assignment_id/submissions/update_grades`
* **Authentication:** OAuth 2.0 `Bearer` access token (requires `url:POST|/api/v1/courses/:course_id/assignments/:assignment_id/submissions/update_grades` scope).
* **Path Parameters:**
  * `course_id` (Integer): The unique Canvas identifier for the course (e.g., `102`).
  * `assignment_id` (Integer): The unique Canvas identifier for the assignment (e.g., `405`).

### JSON Request Payload Schema

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "CanvasBatchGradePassbackRequest",
  "type": "object",
  "properties": {
    "grade_data": {
      "type": "object",
      "additionalProperties": {
        "type": "object",
        "properties": {
          "posted_grade": { "type": "string", "example": "96.5" },
          "text_comment": { "type": "string", "example": "Excellent architectural synthesis and comprehensive error handling." },
          "excused": { "type": "boolean", "example": false }
        },
        "required": ["posted_grade"]
      },
      "description": "Dictionary mapping Canvas User IDs (as string keys) to grading objects."
    }
  },
  "required": ["grade_data"]
}
```

### JSON Response Schema (`200 OK` - Progress Object)

```json
{
  "id": 90421,
```

## HTTP Status Code Reference & Error Catalog

Our APIs follow standard HTTP status code conventions. All non-2xx responses include an RFC 7807 problem details JSON object containing diagnostic metadata to aid developer debugging.

| Status Code | Status Name | Semantic Definition & Trigger Conditions |
| :--- | :--- | :--- |
| `200 OK` | OK | The request succeeded and the requested resource or state modification is returned in the payload. |
| `202 Accepted` | Accepted | The request was accepted for asynchronous processing (e.g., large batch grade passback tasks). Check the returned progress `id`. |
| `400 Bad Request` | Bad Request | Malformed JSON schema, missing required fields, or invalid enum parameters (e.g., passing `quality: 'super'` instead of `ultra`). |
| `401 Unauthorized` | Unauthorized | Missing, expired, or malformed authentication header (`Authorization: Bearer` or `X-Raised-Signature`). |
| `403 Forbidden` | Forbidden | Credentials are valid, but the caller lacks required permissions or scopes (`insufficient_scope`). |
| `429 Too Many Requests` | Too Many Requests | Rate limit exceeded according to token bucket calculations. Inspect the `Retry-After` header for seconds remaining before replenishment. |
| `500 Internal Server Error` | Internal Server Error | An unexpected server-side exception occurred inside our AWS Lambda or database connection pool. Contact support with the `traceId`. |

### Standard RFC 7807 Error Response Schema

```json
{
  "code": "INVALID_PAYLOAD_SCHEMA",
  "message": "Field 'gpuTelemetry.fpsAverage' must be a number between 1 and 240.",
  "traceId": "req_1a2b3c4d5e6f7a8b9c0d",
  "timestamp": "2026-07-22T20:55:19.890Z",
  "documentationUrl": "https://sharonwang.me/developer-docs/api-reference/#http-status-code-reference"
}
```
