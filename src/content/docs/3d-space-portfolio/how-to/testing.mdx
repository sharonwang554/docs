# Testing Guide

## Overview

This project uses Vitest as the test runner with React Testing Library for component testing. The test suite includes unit tests, integration tests, and coverage reporting.

## Test Scripts

### Development

```bash
# Run tests in watch mode
bun run test:watch

# Run tests with UI
bun run test:ui

# Run all tests once
bun test
```

### Coverage

```bash
# Generate coverage report
bun run test:coverage

# Generate coverage for CI (JSON + text output)
bun run test:coverage:ci
```

### Test Categories

```bash
# Run only unit tests (excludes integration tests)
bun run test:unit

# Run only integration tests
bun run test:integration

# Run all tests including SEO checks
bun run test:all
```

### CI/CD

```bash
# Run tests with verbose output and coverage (for CI)
bun run test:ci
```

## Environment Variables

### Test Environment

The following environment variables are used in tests:

- `VITE_MAIL_SERVICE`: Access key for Web3Forms API (defaults to "test-access-key" in tests)
- `NODE_ENV`: Set to "test" during test execution
- `VITE_VERCEL_ANALYTICS_ID`: Disabled in test environment
- `VITE_VERCEL_SPEED_INSIGHTS_ID`: Disabled in test environment

### Configuration Files

- `.env.test`: Test-specific environment variables
- `src/__tests__/setup.ts`: Global test setup and mocks
- `vite.config.ts`: Test configuration and coverage settings

## Coverage Thresholds

### Global Thresholds

- **Lines**: 85%
- **Functions**: 85%
- **Statements**: 85%
- **Branches**: 80%

### Per-File Thresholds

Critical components have higher thresholds:

- **Contact Component**: 95% lines/functions/statements, 90% branches
- **LanguageContext**: 90% lines/functions/statements, 85% branches
- **useFormStatus Hook**: 95% lines/functions/statements, 90% branches

## Coverage Exclusions

The following files/directories are excluded from coverage:

- Test files (`src/__tests__/`)
- Type definitions (`**/*.d.ts`)
- Assets (`src/assets/`)
- 3D components (`src/components/Earth/`, `src/components/SpaceBackground/`)
- Shader files (`src/components/**/shaders.ts`)
- Style files (`**/*.scss`, `**/*.css`)
- Configuration files (`*.config.*`)
- Build output (`dist/`, `public/`)

## CI/CD Integration

### GitHub Actions

The project includes CI workflows that:

1. Run on Node.js 18.x and 20.x
2. Execute linting and type checking
3. Run the full test suite with coverage
4. Build the project to ensure no build errors
5. Deploy to Vercel on successful builds

### Environment Setup

In CI environments:

- Tests run with `NODE_ENV=test`
- Coverage reports are generated in JSON format
- Failed tests are retried once
- Verbose output is enabled for better debugging

## Writing Tests

### Component Tests

```typescript
import { render, screen } from "@/__tests__/utils/render";
import { MyComponent } from "./MyComponent";

test("should render correctly," () => {
  render(<MyComponent />);
  expect(screen.getByText("Expected Text")).toBeInTheDocument();
});
```

### Hook Tests

```typescript
import { renderHook, act } from "@testing-library/react";
import { useMyHook } from "./useMyHook";

test("should handle state correctly," () => {
  const { result } = renderHook(() => useMyHook());

  act(() => {
    result.current.updateState("new value");
  });

  expect(result.current.state).toBe("new value");
});
```

### Async Tests

```typescript
import { waitFor } from "@testing-library/react";

test("should handle async operations," async () => {
  render(<AsyncComponent />);

  await waitFor(() => {
    expect(screen.getByText("Loaded")).toBeInTheDocument();
  });
});
```

## Troubleshooting

### Common Issues

1. **Tests timing out**: Increase `testTimeout` in vite.config.ts
2. **Coverage not meeting thresholds**: Check excluded files and adjust thresholds
3. **Mock issues**: Ensure mocks are properly set up in `src/__tests__/setup.ts`
4. **Environment variables**: Verify `.env.test` file and vite.config.ts env settings

### Debug Mode

```bash
# Run tests with debug output
DEBUG=* bun test

# Run specific test file
bun test -- Contact.test.tsx

# Run tests matching pattern
bun test -- --grep "form submission"
```
