The 3D Space Portfolio employs a robust styling architecture designed to handle a complex UI while preventing CSS specificity wars and global namespace pollution. We utilize **SCSS Modules** coupled with strict **BEM (Block Element Modifier)** naming conventions.

## Architecture & Principles

The styling system is built on three core pillars:

1. **Scoping**: All component styles must be scoped using CSS Modules (`*.module.scss`).
2. **Predictability**: Class names follow the `block__element--modifier` pattern.
3. **Tokenization**: All magic numbers (colors, z-indexes, font sizes) are extracted into CSS Custom Properties (Variables).

## Design Tokens (CSS Variables)

We define our design tokens in a global `_variables.scss` file, which maps SCSS variables to native CSS Custom Properties. This allows for runtime theme switching (like Dark Mode) without JavaScript recalculations.

```scss
/* src/styles/_variables.scss */

:root {
  /* Colors */
  --color-space-black: #050505;
  --color-star-white: #f8f9fa;
  --color-brand-accent: #4cc9f0;
  
  /* Typography */
  --font-primary: 'Inter', system-ui, sans-serif;
  --font-mono: 'Fira Code', monospace;
  
  /* Z-Index Hierarchy */
  --z-canvas: 0;
  --z-overlay: 10;
  --z-navigation: 100;
  --z-modal: 1000;
  
  /* Spacing */
  --space-sm: 0.5rem;
  --space-md: 1rem;
  --space-lg: 2rem;
  --space-xl: 4rem;
}
```

## SCSS Modules + BEM Convention

By combining SCSS Modules with BEM, we get the best of both worlds: guaranteed unique class names in the final bundle, and highly readable, structured code in development.

<Aside type="note">
  When using SCSS Modules, Vite hashes the class name (e.g., `.Hero__title--active_x9f2a`). BEM ensures the logic within the component remains perfectly organized.
</Aside>

### Example: The Hero Component

```scss
/* Hero.module.scss */
@import '../../styles/mixins';

.Hero {
  /* Block */
  display: flex;
  flex-direction: column;
  min-height: 100vh;
  padding: var(--space-xl);
  
  &__title {
    /* Element */
    font-family: var(--font-primary);
    font-size: 4rem;
    color: var(--color-star-white);
    
    &--highlight {
      /* Modifier */
      color: var(--color-brand-accent);
    }
  }

  &__cta {
    /* Element */
    margin-top: var(--space-lg);
    
    @include responsive(md) {
      margin-top: var(--space-xl);
    }
  }
}
```

```tsx
// Hero.tsx
import styles from './Hero.module.scss';

export const Hero = () => {
  return (
    <section className={styles.Hero}>
      <h1 className={styles.Hero__title}>
        Hello, I'm <span className={styles.Hero__title__highlight}>Sharon</span>
      </h1>
      <button className={styles.Hero__cta}>Explore Portfolio</button>
    </section>
  );
};
```

## Global Overrides and Third-Party Styling

Occasionally, you need to style elements outside of your component's scope (e.g., a third-party tooltip or a dynamically injected DOM node). SCSS Modules provides the `:global()` pseudo-selector for this exact scenario.

```scss
.PortfolioCard {
  border: 1px solid rgba(255, 255, 255, 0.1);
  
  /* Styling a third-party slider library injected inside this component */
  :global(.swiper-pagination-bullet) {
    background-color: var(--color-brand-accent);
    opacity: 0.8;
  }
}
```

## Migration Checklist: Adding a New Component

When introducing a new UI component to the portfolio, follow these steps to ensure compliance with the styling system:

<Steps>
1. Create a `ComponentName.tsx` and a sibling `ComponentName.module.scss`.
2. Define the root class name exactly matching the component name (e.g., `.ComponentName`).
3. Import CSS custom properties for any colors, spacing, or typography. **Do not hardcode hex values.**
4. Use `&__element` for child nodes and `&--modifier` for state variations.
5. If defining media queries, use the predefined mixins (e.g., `@include responsive(sm)`).
</Steps>
