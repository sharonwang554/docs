## Integration Architecture & Scope

Integrating custom tools with **Canvas LMS** requires coordinating **LTI 1.3/1.1** launches, **OAuth 2.0** token rotation, and **REST API / SIS sync** jobs across AWS serverless microservices. When integrations fail in production, Technical Support Engineers must rapidly isolate the failure domain. This runbook documents **5 real-world integration errors** adhering strictly to our **Standard Operating Procedure (SOP)** format: **`Symptom → Diagnosis → Fix → Prevention`**.

---

## 1. `401 Unauthorized` & Expired OAuth Refresh Tokens

### Symptom
Nightly background roster and grading synchronization workers fail with `HTTP 401 Unauthorized` (`{"status": "unauthorized", "errors": [{"message": "Invalid access token."}]}`).

### Diagnosis
Canvas OAuth 2.0 access tokens have a strict Time-To-Live (TTL) of **3600 seconds (1 hour)**. Background sync workers must exchange the `refresh_token` via `POST /login/oauth2/token` before expiration. A `401 Unauthorized` indicates **token rotation failure**:
1. **Transient Network Timeout during Refresh**: The worker requested a token, but the connection dropped before persistence. Because single-use rotation invalidates old tokens upon issuing new ones, the worker holds an expired `access_token` and an invalidated `refresh_token`.
2. **Database Concurrency Race Condition**: Multiple AWS Lambda instances attempted rotation simultaneously using the same `refresh_token`, causing `invalid_grant` rejection on secondary requests.

### Fix (Step-by-Step Resolution)

<Steps>
1. **Verify Token Status in AWS Secrets Manager**
   Inspect the stored payload (`expires_at` against current UTC time):
   ```bash
   aws secretsmanager get-secret-value --secret-id prod/canvas/oauth-tokens --query 'SecretString' --output text | jq .
   ```
2. **Execute Manual OAuth Refresh via cURL**
   If the `refresh_token` is still valid, request a fresh `access_token` using client credentials:
   ```bash
   curl -X POST "https://canvas.instructure.com/login/oauth2/token" -d "grant_type=refresh_token&client_id=10001&client_secret=CLIENT_SECRET&refresh_token=STORED_REFRESH"
   ```
3. **Update Secret Store & Flush Redis Cache**
   If step 2 returns `200 OK`, update Secrets Manager and clear Redis token cache:
   ```bash
   aws secretsmanager put-secret-value --secret-id prod/canvas/oauth-tokens --secret-string '{"access_token":"NEW_TOKEN","refresh_token":"NEW_REFRESH","expires_at":1721685000}'
   redis-cli -h prod-redis DEL "canvas:token:cache:10001"
   ```
4. **Re-Authenticate via Admin Consent Flow (If Refresh Failed)**
   If step 2 returns `invalid_grant`, direct the administrator to the OAuth initiation endpoint (`https://api.example.com/v1/auth/canvas/login`) to re-authorize the application.
</Steps>

### Prevention
- **Atomic Mutex Locking**: Enforce distributed locking (Redis `SETNX`) across the cluster so only one worker executes token renewal.
- **Proactive Renewal Buffer**: Initiate renewal **10 minutes before** `expires_at` rather than waiting for `401 Unauthorized` errors.

## 2. `429 Too Many Requests` & Leaky Bucket Throttling

### Symptom
Bulk enrollment syncs drop requests with `HTTP 429 Too Many Requests`, header `X-Rate-Limit-Remaining: 0.000`, and `Retry-After: 45`.

### Diagnosis
Canvas enforces a **Leaky Bucket Algorithm (`Cost vs. Capacity`)**:
- Each API request incurs a `cost` (`GET /users/self` = `1.0` vs `GET /courses/:id/enrollments?include[]=total_scores` > `12.0`).
- Each token has a maximum `capacity` (`700.0` points) recovering at a fixed rate (`10.0` points/sec).
- Bursts of complex queries depleting capacity faster than recovery trigger `HTTP 429`.

### Fix (Step-by-Step Resolution)

<Tabs>
  <TabItem label="Node.js Backoff Interceptor">
    Apply **Full Jitter Exponential Backoff** inside an Axios response interceptor:
    ```typescript
    import { AxiosInstance, AxiosError } from 'axios';
    export function attachRateLimitGuard(client: AxiosInstance): void {
      client.interceptors.response.use((res) => res, async (error: AxiosError) => {
        if (!error.config || error.response?.status !== 429) return Promise.reject(error);
        const attempt = (error.config as any)._retry || 1;
        if (attempt > 5) return Promise.reject(new Error('Rate limit retries exceeded'));
        const retryAfter = parseInt(error.response.headers['retry-after'] || '10', 10);
        const delayMs = Math.max(retryAfter * 1000, (1000 * Math.pow(2, attempt)) + Math.floor(Math.random() * 1000));
        await new Promise((r) => setTimeout(r, delayMs));
        (error.config as any)._retry = attempt + 1;
        return client.request(error.config);
      });
    }
    ```
  </TabItem>
  <TabItem label="Python / Celery Backoff">
    Leverage Celery's `self.retry` with exponential backoff on `HTTP 429`:
    ```python
    @shared_task(bind=True, max_retries=5)
    def sync_roster(self, course_id: int):
        resp = requests.get(f"https://canvas.instructure.com/api/v1/courses/{course_id}/enrollments", headers={"Authorization": "Bearer TOKEN"})
        if resp.status_code == 429:
            backoff = max(int(resp.headers.get("Retry-After", 10)), (2 ** self.request.retries))
            raise self.retry(countdown=backoff)
        resp.raise_for_status()
        return resp.json()
    ```
  </TabItem>
</Tabs>

### Prevention
- **Migrate to GraphQL**: Replace nested REST loops with batched **Canvas GraphQL API (`POST /api/graphql`)** queries.
- **Event-Driven Sync**: Subscribe to AWS SQS / EventBridge webhooks (`submission_created`, `enrollment_created`).

## 3. LTI Launch OAuth Signature Mismatch (`OAuthSignatureException`)

### Symptom
When users launch an LTI tool inside Canvas, the iframe displays `Invalid OAuth Signature. OAuthSignatureException: Signature validation failed`.

### Diagnosis
LTI 1.1 uses OAuth Core 1.0a HMAC-SHA1 signatures; LTI 1.3 uses OIDC/JWT `RS256` verification. Failures occur due to:
1. **Server Clock Drift (`oauth_timestamp`)**: Verifiers reject timestamps drifting over **300 seconds (5 minutes)** from UTC to prevent replay attacks.
2. **Reverse Proxy Protocol Stripping**: If an AWS Application Load Balancer (ALB) terminates SSL and forwards requests via plain `http://`, verifiers construct base strings using `http://` instead of registered `https://` URLs.

### Fix (Step-by-Step Resolution)

<Steps>
1. **Audit Container NTP Synchronization**
   Verify host clock drift (`chronyc tracking`) is strictly within $\pm 0.05\text{ seconds}$ of NTP reference.
2. **Verify Reverse Proxy Protocol Headers**
   Configure Express / Node microservices to trust `X-Forwarded-Proto` proxy headers:
   ```javascript
   app.set('trust proxy', true);
   app.post('/lti/launch', (req, res, next) => {
     const protocol = req.headers['x-forwarded-proto'] || req.protocol;
     console.log(`[LTI Debug] Verifying against: ${protocol}://${req.get('host')}${req.originalUrl}`);
     next();
   });
   ```
3. **Verify LTI 1.3 JWKS Public Key Rotation**
   Ensure your tool's JWKS endpoint (`https://api.example.com/.well-known/jwks.json`) contains active `kid` headers matching launch JWTs:
   ```bash
   curl -s https://api.example.com/.well-known/jwks.json | jq .keys[].kid
   ```
</Steps>

### Prevention
- Enforce `HTTPS-only` API Gateway custom domains passing `CloudFront-Forwarded-Proto` to Lambda events.
- Cache Canvas JWKS platform keys locally with automatic retry fetches upon unknown `kid` headers.

## 4. Cross-Origin Resource Sharing (CORS) Preflight Blocks

### Symptom
Canvas widgets executing `fetch()` against AWS API Gateway endpoints fail (`Access to fetch blocked by CORS policy`).

### Diagnosis
Browsers send an `OPTIONS` preflight before credentialed calls. Blocks occur when:
1. **Authorizer Execution on `OPTIONS`**: Browsers omit `Authorization` headers on `OPTIONS` preflights, causing Lambda Authorizers to return `401 Unauthorized`.
2. **Missing Access-Control Headers**: The `OPTIONS` response omits `Access-Control-Allow-Origin` and `Access-Control-Allow-Headers`.

### Fix (Step-by-Step Resolution)

<Aside type="caution">
**No Wildcard Origins with Credentials**
If your frontend sends `Access-Control-Allow-Credentials: true` or cookies/Bearer headers, setting `Access-Control-Allow-Origin: *` is forbidden. You must explicitly reflect exact origins.
</Aside>

Configure AWS SAM to serve an `OPTIONS` mock integration bypassing authorizers:
```yaml
Resources:
  CanvasSyncApi:
    Type: AWS::Serverless::Api
    Properties:
      StageName: prod
      Cors:
        AllowMethods: "'GET,POST,OPTIONS'"
        AllowHeaders: "'Content-Type,Authorization,X-Correlation-ID'"
        AllowOrigin: "'https://canvas.instructure.com'"
      Auth:
        DefaultAuthorizer: LambdaTokenAuthorizer
        Authorizers:
          LambdaTokenAuthorizer:
            FunctionArn: !GetAtt AuthorizerFunction.Arn
            Identity:
              Headers:
                - Authorization
```

Ensure Lambda responses return exact CORS headers:
```typescript
export const handler = async (event: any) => {
  const headers = {
    'Access-Control-Allow-Origin': 'https://canvas.instructure.com',
    'Access-Control-Allow-Headers': 'Content-Type,Authorization,X-Correlation-ID',
    'Access-Control-Allow-Methods': 'OPTIONS,POST,GET'
  };
  return { status: 200, headers, body: JSON.stringify({ success: true }) };
};
```

## 5. Grade Passback Payload Validation Failures

### Symptom
Nightly grading sync jobs report `Failed` when posting updates (`422 Unprocessable Entity` or `400 Bad Request`).

### Diagnosis
Failures originate from two validation mismatches:
1. **Identifier Mapping Mismatch (`user_id` vs `sis_user_id`)**: The tool sends internal database IDs while Canvas expects `canvas_user_id` integers or `sis_user_id:STU-98765`.
2. **Precision Overflow**: Double-precision floats (`85.66666666666667`) sent without rounding violate 2-decimal Canvas validation or exceed `points_possible`.

### Fix (Step-by-Step Resolution)

<Steps>
1. **Audit Student Mapping via API**
   Verify valid `sis_user_id` bindings before submitting grades:
   ```bash
   curl -s -X GET "https://canvas.instructure.com/api/v1/courses/10495/users?include[]=sis_user_id" -H "Authorization: Bearer TOKEN" | jq .
   ```
2. **Sanitize & Format Grade Passback Payloads**
   Enforce strict 2-decimal rounding and valid identifier mappings:
   ```typescript
   export function buildGradePayload(submissions: Array<{ canvasId: number; score: number; max: number }>) {
     const grade_data: Record<string, any> = {};
     for (const sub of submissions) {
       const rounded = Math.round((sub.score + Number.EPSILON) * 100) / 100;
       grade_data[String(sub.canvasId)] = {
         posted_grade: `${Math.min(rounded, sub.max)}`,
         text_comment: `Automated Sync - Verified on ${new Date().toISOString().split('T')[0]}`
       };
     }
     return { grade_data };
   }
   ```
3. **Execute Idempotent Batch Passback**
   Dispatch the batch payload and monitor the async `Progress` tracking object:
   ```bash
   curl -X POST "https://canvas.instructure.com/api/v1/courses/10495/assignments/20938/submissions/update_grades" -H "Authorization: Bearer TOKEN" -H "Content-Type: application/json" -d @grades.json
   ```
</Steps>

### Prevention
- **Pre-Sync Zod Validation**: Validate against JSON Schemas prior to dispatch, routing malformed entries to a Dead-Letter Queue (`CanvasGradeDLQ`).
- **Nightly Enrollment Reconciliation**: Schedule daily automated audits comparing local rosters against Canvas `GET /api/v1/courses/:id/enrollments` snapshots.
